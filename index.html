Origin Story…

About Me

Self-taught and Guwahati-based, driven by one recurring instinct: noticing where people are stuck, and quietly making it easier.

Currently based in Guwahati.

It all started with a love for making things work better — and once that door opened, there was no closing it.

What began as formulated Excel sheets quickly grew into something else entirely. A shared network downtime tracker used across multiple units. A patient journey turnaround sheet pulling live data from different departments. Print job counters, vendor ticket trackers, radiology and lab machine usage reports — all built because someone had a manual process and I couldn't help but wonder if there was a better way. Then a senior colleague showed me Active Directory Server Policies, and something clicked. Scripts, Group Policies, print server management, login trackers — each one a new puzzle, each solution a reason to go deeper.

Soon after, I fell headfirst into Docker and the world of open source software. Form a rudimentary idea of using Google Form with a Telegram integration as a Service Request system became a self-hosted ecosystem of 19 actively maintained applications, each one chosen to solve a specific problem — DNS management, internal domain routing, asset tracking, a ticketing system, building-wide media signage, a reception call log, document automation. Alongside this, I oversee HMIS, PACS, and lab equipment integration across clinical systems.

Nobody told me to do any of it. But noticing the pain points of the people around you — and quietly making them disappear is a satisfaction of a different level.

Naming Convention vs. Remembering IP Addresses

Internal apps lived at random IPs and ports — which nobody could remember. Built an internal DNS so every app gets a clean, memorable address.

Technitium DNS · Caddy · Docker

Naming Convention vs. Remembering IP Addresses

// what was broken

Accessing any self-hosted app meant remembering a raw IP and port — 192.168.x.x:8080 style addresses that nobody could keep straight, let alone share with non-technical colleagues. Every new app added another combination to memorise.

// what was built

Technitium DNS now resolves clean internal domains like tv.loc and home.loc across the LAN, with Caddy handling reverse proxying and automatic HTTPS for each one. Anyone on the network can type a name instead of hunting for an address.

Technitium DNS · Caddy · Docker

Visitor Register, Digitized

Visitor entries were logged on registers — illegible, easy to lose, and impossible to search. Built a digital visitor register with signatures, timestamps, and role-based access.

Saltcorn · Docker · PostgreSQL

Visitor Register, Digitized

// what was broken

Visitor logs lived on paper at the front desk — handwriting nobody could read later, no way to search past entries, and no real record if a register page went missing. Auditing who visited, when, and why meant flipping through stacks of paper.

// what was built

A self-hosted digital visitor register built on Saltcorn, with a signature pad for visitor sign-in, automatic date/time stamping on every entry, and role-based access so front desk staff and management see exactly what they need — nothing more. Every entry is now instantly searchable, with a permanent, tamper-resistant record.

Saltcorn · Docker · PostgreSQL
